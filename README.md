# BMS–EMS research project

This repository studies battery state-of-health (SOH) estimation and dual-motor
battery-electric-vehicle energy management.

Start with [the measured research progress report](RESEARCH_PROGRESS.md) and
[the enhancement and validation plan](ENHANCEMENT_PLAN.md). New experiments are
stored under `research_runs/`; the original datasets, checkpoints and result
files are retained separately.

## Implemented models

**BMS.** [CNNTCNLSTMAttention](bms_gtr/src/models/hybrid_model.py) has 150,465
trainable parameters: a per-cycle CNN, residual TCN blocks, an LSTM, additive
attention and a sigmoid regressor. Inputs have shape `[batch, 20, 3, 300]`.
The channels are dQ/dV, dV/dQ and dI/dV, generated by
[the feature extractor](bms_gtr/src/features/electrochemical.py).
The target is the next retained discharge cycle's capacity divided by that
battery's first usable capacity.

The supplied processed data contains 556 sequences from B0005, B0006, B0007 and
B0018. The original raw NASA `.mat` files are absent from this workspace.
The new benchmark verifies exact reconstruction from the per-battery processed
archives; it does not regenerate or independently validate the raw measurements.

**EMS.** [EnergyManagementEnv](ems_yash/src/environment/rl_environment.py)
combines longitudinal vehicle dynamics, two geared motors, digitized efficiency
maps, a two-RC battery model, component-aging models and a Gymnasium interface.
[DDPG and history networks](ems_yash/src/agent/ddpg_agent.py) are implemented,
but the repository has no trained EMS checkpoint.

Actions remain normalized in replay and the learning networks. The environment
maps them to the complete feasible torque-split interval under the configured
torque/speed limits. Motor power
uses interval-average speed, and endpoint feasibility is checked before stepping.
Positive battery power/current denotes charging; positive motor electrical
power denotes battery discharge.

## Reproducible experiments

The new runners were exercised with Python 3.11.7. Their manifests record the
actual dependency versions, configuration, source hashes and input hashes.
The BMS mean/ridge paths require NumPy; the hybrid also requires PyTorch.
The EMS runner requires NumPy, SciPy, pandas, Gymnasium and PyTorch. No dependency
installation is performed by either runner.

Run these commands from the repository root in a suitable environment:

```sh
python -B bms_gtr/scripts/run_purged_lobo.py \
  --output-dir research_runs/my_bms_run \
  --models mean ridge hybrid --seed 42 --max-epochs 40

python -B ems_yash/run_controlled_benchmark.py \
  --output-dir research_runs/my_ems_run
```

Each output directory must be new. Existing output directories are refused.

The [BMS protocol](bms_gtr/src/evaluation/purged_lobo.py) holds out one entire
battery at a time. It uses chronological validation within the remaining
batteries, purges 20 sequence rows at each training/validation boundary, and fits
channel scaling only on retained training inputs. Training-mean, ridge and the
unchanged hybrid architecture share these partitions. Ridge selection and neural
checkpoint selection use inner validation only. Saved predictions retain battery
and source-cycle identifiers. Reported errors are SOH fractions; 0.01 equals one
percentage point.

Load a saved predictor from the BMS project directory:

```python
from src.evaluation.purged_lobo import load_frozen_predictor

predict = load_frozen_predictor(
    "../research_runs/my_bms_run/folds/B0005", "ridge"
)
predictions = predict(raw_sequences)  # [N, 20, 3, 300], before scaling
```

Use the corresponding fold's saved scaler and model together.

The [EMS benchmark](ems_yash/run_controlled_benchmark.py) compares five declared
controllers on all six supplied standard cycles: fixed normalized action, the
SOH rule with correct information, two SOH-underestimation cases, and a
101-action one-step electrical-energy reference. It records completed distance,
energy, current, physical modeled aging and constraint failures. These are
simulation comparisons; the grid reference is not a trained RL controller or a
global trajectory optimum.

## Verification

Run the two projects' checks in separate processes because both use a top-level
package named `src`.

From `bms_gtr/`:

```sh
python -B -m unittest src.evaluation.test_purged_lobo
```

From `ems_yash/`:

```sh
python -B -m unittest \
  src.bms_interface.test_soh_trace_adapter \

  src.environment.test_step_energy \
```

artifact verification performed for this enhancement.

From the repository root, the controlled-benchmark checks are:

```sh

```

[the BMS run](research_runs/bms_purged_lobo_seed42/summary.json) and

## Interpretation and remaining work

- The neural benchmark is a single-seed pilot with a declared epoch budget.
  It is not evidence of convergence or universal model superiority.
- Short simulated SOH changes are outputs of inherited degradation equations,
  not measured lifetime extension. Thermal and aging calibration remain open.
- Digitized efficiency maps, nearest-neighbor extrapolation and timestep
  sensitivity limit small energy claims.
- In the general `BMS_ESTIMATED` environment mode, estimated SOH enters
  observations, rewards and SOH constraint checks. The controlled-bias benchmark
  instead keeps the environment in `TRUE_PHYSICAL` mode and changes only a
  copied controller observation, so its evaluation remains tied to physical
  simulated state.
- Mapping NASA-cell predictions to the simulated vehicle battery and aligning
  their timescales remain unresolved. The controlled-bias study does not claim
  learned online BMS–EMS feedback or reproduction of either paper's results.

## Historical material and base papers

The original [BMS results](bms_gtr/results/) and
[EMS Phase 3B report](ems_yash/docs/phase3b_results_report.md) remain available as
historical artifacts. Their protocols differ from the new experiments.
In particular, historical all-data BMS scores are not independent test scores,
and the legacy fresh-plant versus held-estimate SOH difference is not a paired
NASA prediction error. Use the new report for current measured claims.

The supplied base papers are
[the EMS paper](1-s2.0-S0378775324014150-main.pdf) and
[the BMS paper](b3.pdf). Additional component documentation is in
[bms_gtr/](bms_gtr/README.md) and [ems_yash/](ems_yash/README.md);
older phase descriptions should be read alongside the current progress report.
