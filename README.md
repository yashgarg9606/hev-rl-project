# BMS–EMS research project

This repository studies battery state-of-health (SOH) estimation and dual-motor
battery-electric-vehicle energy management.

Start with [the measured research progress report](RESEARCH_PROGRESS.md) and
[the current audit-remediation record](REMEDIATION.md). The
[initial enhancement plan](ENHANCEMENT_PLAN.md) records the earlier work. Experiments are
stored under `research_runs/`; the original datasets, checkpoints and result
files are retained separately.

The uploaded project's bulk `data/raw/` measurements and generated
`data/processed/sequences.npz` archive remain local and are excluded from Git.
A fresh clone includes its source, per-cell processed archives and small
historical checkpoints/results, but needs the corresponding local inputs before
running commands that read the excluded files. The artifact hashes in
[the preservation record](research_runs/remediation_verification_20260927/preservation.json)
identify the retained local inputs; that record does not distribute them.

## Implemented models

**NASA BMS.** [CNNTCNLSTMAttention](bms_gtr/src/models/hybrid_model.py) has 150,465
trainable parameters: a per-cycle CNN, residual TCN blocks, an LSTM, additive
attention and a sigmoid regressor. Inputs have shape `[batch, 20, 3, 300]`.
The channels are dQ/dV, dV/dQ and dI/dV, generated by
[the feature extractor](bms_gtr/src/features/electrochemical.py).
The target is the next retained discharge cycle's capacity divided by that
battery's first usable capacity.

The supplied processed data contains 556 sequences from B0005, B0006, B0007 and
B0018. Raw `.mat` files for these cells are now present in
[the uploaded project's NASA directory](battery-health-cnn-tcn-lstm-main/data/raw/NASA/Batteries/).
The completed benchmark starts from the per-battery processed archives and
verifies their sequence reconstruction. It does not establish raw measurement
quality or a cell-to-vehicle calibration.

**Uploaded BMS variant.**
[The separate project](battery-health-cnn-tcn-lstm-main/) adds spatial attention
and a fourth voltage-coverage channel. Its default model has 150,690 parameters
and returns the prediction plus temporal and spatial attention. Its supplied
9,531 sequences come from 20 `K_*` cells and eight `H_*` cells; the copied NASA
archives are not included in that combined training dataset. Provided Kaggle
labels have unverified provenance, while the HalfCycle labels are discharge-window
capacity proxies. They must not be pooled or presented as validated battery SOH.
Its historical checkpoint and copied NASA experiment outputs do not constitute
an independent evaluation of this variant.

**EMS.** [EnergyManagementEnv](ems_yash/src/environment/rl_environment.py)
combines longitudinal vehicle dynamics, two geared motors, digitized efficiency
maps, a two-RC battery model, component-aging models and a Gymnasium interface.
[DDPG and history networks](ems_yash/src/agent/ddpg_agent.py) are implemented,
but the repository has no trained EMS checkpoint. DDPG defaults to fully connected
layers of width 64 and a recurrent width of 50. The earlier fully connected
configuration is explicit through `hidden_dim=50`.

Actions remain normalized in replay and the learning networks. The environment
maps them to the complete feasible torque-split interval under the configured
torque/speed limits. Motor power
uses interval-average speed, and endpoint feasibility is checked before stepping.
Positive battery power/current denotes charging; positive motor electrical
power denotes battery discharge.

The environment validates cycle demands against its observation contract before
starting. Failed physical or environment steps restore model-owned state, so an
exception does not leave the plant partly advanced.

## Reproducible experiments

The completed runners were exercised with Python 3.11.7. Their manifests record
the dependency versions, configuration, source hashes and input hashes at the
time of those runs. Later source fixes do not rewrite those historical manifests.
The BMS mean/ridge paths require NumPy; the hybrid also requires PyTorch.
The EMS runner requires NumPy, SciPy, pandas, Gymnasium and PyTorch. No dependency
installation is performed by either runner.

Run these commands from the repository root in a suitable environment:

```sh
python -B bms_gtr/scripts/run_purged_lobo.py \
  --output-dir research_runs/my_bms_run \
  --models mean ridge hybrid --seed 42 --max-epochs 40

python -B ems_yash/run_controlled_benchmark.py \
  --output-dir research_runs/my_ems_run
```

Each output directory must be new. Existing output directories are refused.

The [BMS protocol](bms_gtr/src/evaluation/purged_lobo.py) holds out one entire
battery at a time. It uses chronological validation within the remaining
batteries, purges 20 sequence rows at each training/validation boundary, and fits
channel scaling only on retained training inputs. Training-mean, ridge and the
unchanged hybrid architecture share these partitions. Ridge selection and neural
checkpoint selection use inner validation only. Saved predictions retain battery
and source-cycle identifiers. Reported errors are SOH fractions; 0.01 equals one
percentage point.

Load a saved predictor from the BMS project directory:

```python
from src.evaluation.purged_lobo import load_frozen_predictor

predict = load_frozen_predictor(
    "../research_runs/my_bms_run/folds/B0005", "ridge"
)
predictions = predict(raw_sequences)  # [N, 20, 3, 300], before scaling
```

Use the corresponding fold's saved scaler and model together.

The [EMS benchmark](ems_yash/run_controlled_benchmark.py) compares five declared
controllers on all six supplied standard cycles: fixed normalized action, the
SOH rule with correct information, two SOH-underestimation cases, and a
101-action one-step electrical-energy reference. It records completed distance,
energy, current, physical modeled aging and constraint failures. These are
simulation comparisons; the grid reference is not a trained RL controller or a
global trajectory optimum.

The uploaded variant has its own
[purged evaluation runner](battery-health-cnn-tcn-lstm-main/scripts/run_purged_lobo.py).
Select cells from one target family and explicitly acknowledge that the supplied
labels are uncertified. For example, to exercise the mean-baseline protocol:

```sh
python -B battery-health-cnn-tcn-lstm-main/scripts/run_purged_lobo.py \
  --output-dir research_runs/my_spatial_protocol_run \
  --batteries K_0001 K_0002 K_0003 --models mean \
  --acknowledge-unverified-targets
```

This example is not a declared scientific comparison. The runner records target
meaning and provenance limits; neither acknowledgment nor holding out a cell
turns an unverified label into calibrated health. Corrected preprocessing must be
paired with a newly fitted model, not a historical checkpoint trained on a
different feature schema.

## Explicit offline trace export

[The trace exporter](ems_yash/generate_bms_trace.py) handles a selected cell and
keeps its predictions paired with the original target cycle IDs. Supply a CSV
with columns `battery,target_cycle_id,time_seconds`, one ordered row per target,
and a strictly increasing nonnegative time mapping. The mapping is an explicit
experiment input; it is not inferred from the 20-cycle history length.

With a prepared timestamp CSV, a saved held-out ridge fold can be exported as:

```sh
python -B ems_yash/generate_bms_trace.py \
  --variant legacy --battery B0005 \
  --fold-dir research_runs/bms_purged_lobo_seed42/folds/B0005 --model ridge \
  --timestamps my_b0005_times.csv --output research_runs/my_b0005_trace.npz
```

Existing output files are refused. Historical checkpoint inference is labeled
separately from held-out fold inference; channel/schema mismatches and
discharge-window proxies are rejected. Supplied unverified SOH labels require
explicit acknowledgment. No predictions are silently clipped into range.
The exporter enables offline replay, not validated online cell-to-pack inference.

NASA raw-data rebuilding accepts explicit `--raw-dir` and a new `--output-dir`
through [build_dataset.py](bms_gtr/scripts/build_dataset.py); sequence construction
accepts `--data-dir` and `--output` through
[build_sequences.py](bms_gtr/scripts/build_sequences.py). The NEDC and WLTC
extractors require `--source` for the missing original velocity text and
`--output` for a new CSV. Supplied benchmark CSVs remain available; no substitute
raw measurements or elapsed times are invented.

Historical all-data training/evaluation commands now direct users to the purged
runners. Plot a completed held-out run into a new directory with:

```sh
python -B bms_gtr/scripts/plot_run.py \
  --run-dir research_runs/bms_purged_lobo_seed42 --model ridge \
  --output-dir research_runs/my_bms_plots
```

Plotting additionally requires Matplotlib. The uploaded project provides the
same `scripts/plot_run.py` interface for its own completed runs. Its supported
historical figure generators require an explicit historical-mode acknowledgment
and new output directory; their existence is not validation of the paper's experiments.
Legacy EMS baseline entrypoints also require a new `--output-dir`; the
comparison accepts an explicit `--trace`.

same top-level package name, `src`.

## Interpretation and remaining work

- The neural benchmark is a single-seed pilot with a declared epoch budget.
  It is not evidence of convergence or universal model superiority.
- Short simulated SOH changes are outputs of inherited degradation equations,
  not measured lifetime extension. Thermal and aging calibration remain open.
- Digitized efficiency maps, nearest-neighbor extrapolation and timestep
  sensitivity limit small energy claims.
- In the general `BMS_ESTIMATED` environment mode, estimated SOH enters
  observations, rewards and SOH constraint checks. The controlled-bias benchmark
  instead keeps the environment in `TRUE_PHYSICAL` mode and changes only a
  copied controller observation, so its evaluation remains tied to physical
  simulated state.
- Mapping NASA-cell predictions to the simulated vehicle battery and aligning
  their timescales remain unresolved. The controlled-bias study does not claim
  learned online BMS–EMS feedback or reproduction of either paper's results.

## Historical material and base papers

The original [BMS results](bms_gtr/results/) and
[EMS Phase 3B report](ems_yash/docs/phase3b_results_report.md) remain available as
historical artifacts. Their protocols differ from the new experiments.
In particular, historical all-data BMS scores are not independent test scores,
and the legacy fresh-plant versus held-estimate SOH difference is not a paired
NASA prediction error. Use the new report for current measured claims.

The supplied base papers are
[the EMS paper](1-s2.0-S0378775324014150-main.pdf) and
[the BMS paper](b3.pdf). Additional component documentation is in
[bms_gtr/](bms_gtr/README.md) and [ems_yash/](ems_yash/README.md);
older phase descriptions should be read alongside the current progress report.
